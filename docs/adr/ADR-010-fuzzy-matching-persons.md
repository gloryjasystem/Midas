# ADR-010: Fuzzy Matching for Person Deduplication

**Статус:** ACCEPTED
**Дата:** 2026-05-04

---

## Контекст

Пользователь привязывает расходы к людям свободным текстом: «Макс», «Максим», «Максиму», «максу». Без дедупликации — дубли в базе и искажение отчётов «Расходы по людям». (ТЗ §3.2, PC §4.4, Event Storming R-05, Q-08)

## Рассмотренные варианты

| Алгоритм | Тип | Скорость | Точность для русского | Сложность |
|---|---|---|---|---|
| Levenshtein distance | Edit distance | Быстрый | Средняя (не учитывает падежи) | Низкая |
| Jaro-Winkler | Similarity | Быстрый | Хорошая для коротких имён | Низкая |
| Soundex/Metaphone | Phonetic | Быстрый | ❌ Не работает для кириллицы | — |
| Нормализация + Jaro-Winkler (ВЫБРАН) | Hybrid | Быстрый | Хорошая | Средняя |

## Решение

**Нормализация + Jaro-Winkler** с порогом similarity ≥ 0.85.

### Алгоритм

```
1. Нормализация ввода:
   a. toLowercase()
   b. trim()
   c. Удаление суффиксов падежей: -у, -а, -ом, -е (простая эвристика)
   d. Результат: "Максиму" → "максим", "Максу" → "макс"

2. Поиск кандидатов:
   SELECT * FROM persons WHERE workspace_id = X

3. Jaro-Winkler similarity каждого кандидата vs normalized input:
   - score >= 0.92 → AUTO-SUGGEST (подстановка сильного совпадения, но без авто-слияния сущностей)
   - 0.85 <= score < 0.92 → ASK_CONFIRMATION (спросить пользователя: "Вы имели в виду [Максим]?")
   - score < 0.85 → CREATE (создать нового Person)

4. Human-in-the-Loop при конфликте:
   - Никогда не выполнять автоматическое слияние (merge) разных Person без явного подтверждения.
   - Bot: "Вы имели в виду: [Макс] или [Максим К.]? Или создать нового?"
   - Если пользователь выбрал существующего, привязываем транзакцию к нему.
```

### Порог

- **0.92** — порог сильного совпадения (auto-suggest).
- **0.85** — порог потенциального совпадения (ask user).

## Последствия

- Библиотека: `string-similarity` или `jaro-winkler` (npm)
- `Person` хранит: `canonical_name` (нормализованное) + `aliases[]` (все варианты написания)
- Event `FuzzyMatchConflict` → Inline keyboard для пользователя
- Event `PersonMerged` → при ручном объединении дублей
- Таблица `persons`: индекс на `canonical_name` для быстрого поиска
- Тестирование: набор из 50+ русских имён с падежами для валидации порога
