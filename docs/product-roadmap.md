### Phase 1.23 — `/set_balance` (Синхронизация баланса)

**Зачем:** Пользователь пересчитал деньги — в Midas показывает не ту сумму. Нужно быстро синхронизировать без записи фиктивных транзакций.

**Как работает:**

```
/set_balance Binance 48500

Система внутри:
  1. Находит счёт «Binance»
  2. Считает текущий баланс = initial_balance + Σтранзакций = 52 000
  3. Вычисляет новый initial_balance = 48500 − Σтранзакций
  4. UPDATE account_sources SET initial_balance = новое_значение
  5. Никакой транзакции не создаётся

Ответ бота:
✅ Баланс «Binance» синхронизирован
   Было:  52,000.00 USDT
   Стало: 48,500.00 USDT
```

**Ключевые правила:**
- Это НЕ расход и НЕ доход — техническая корректировка
- `/report` не затрагивается
- Категория не нужна
- Отрицательные значения разрешены (кредитка: `/set_balance Кредитка -65000`)
- Новых таблиц не нужно — используем существующий `initial_balance`

**Файлы:** `balance.service.ts` (MODIFY), `webhook.route.ts` (MODIFY), `smoke-test-phase123.mjs` (NEW)

### Phase 1.25 — `/settings` текстовый (базовый)

**Зачем:** Дать возможность сменить базовую валюту командой, прежде чем делать красивый UI.

**Как работает:**

```
/settings
→ ⚙️ Настройки Midas
  💵 Базовая валюта: USDT
  Изменить: /settings currency BTC

/settings currency BTC
→ ✅ Базовая валюта: BTC
  Теперь «получил 500» = 500 BTC
```

**Правила:**
- Прошлые транзакции НЕ пересчитываются
- Новые транзакции без явной валюты → записываются в новой базовой
- Проверка формата: 3–5 букв латиницей

**Файлы:** `settings.service.ts` (NEW), `webhook.route.ts` (MODIFY), миграция не нужна (`default_currency` уже есть в `workspaces`)

### Phase 1.28 — `/edit` — редактирование транзакций

**Зачем:** Человек записал, подтвердил, а потом увидел ошибку. Нужно точечно исправить.

**Три способа найти транзакцию:**

Способ 1 — Последние:
```
/edit
📋 Последние транзакции:
1. 💸 Binance комиссия — 5.00 USDT      сегодня
2. 💰 Зарплата — 3,500.00 USDT          вчера
3. 💸 Продукты — 2,100.00 RUB           вчера
[◀️] 1/24 [▶️]
[🔍 Поиск] [❌ Закрыть]
```

Способ 2 — Поиск:
```
🔍 Что ищем?
> кофе
→ 3 результата: [Кофе 350 RUB 03.05] [Кофе 420 RUB 28.04]...
```

Способ 3 — Кнопка «Исправить» сразу после записи (5 минут):
```
✅ Записано: Кофе, 350 RUB
[✏️ Исправить] — доступно 5 мин
```

**Карточка транзакции:**
```
📝 Транзакция
💸 Тип:      Расход
💰 Сумма:    350.00 RUB
📁 Категория: Кофе
🏦 Счёт:     Карта Сбер
📅 Дата:     03.05.2026

[✏️ Изменить сумму]
[📁 Изменить категорию]
[🏦 Изменить счёт]
[🔄 Изменить тип]
[🗑️ Удалить]
[◀️ Назад]
```

**Изменение категории:**
```
📁 Выбери новую:
🏢 Бизнес: [Реклама] [Сервисы] [Налоги]
🌍 Жизнь:  [Продукты][Кофе]   [Транспорт]
[🔍 Найти] [✏️ Ввести вручную]
→ ✅ Категория изменена. Баланс пересчитан.
```

**Изменение суммы:**
```
💰 Текущая: 350.00 RUB. Напиши новую:
> 380
→ ✅ Сумма изменена. Баланс пересчитан автоматически.
```

### Phase 1.30 — Умный онбординг счетов

**Зачем:** Новый пользователь не знает что такое «счёт». Система ведёт за руку.

При пустом `/accounts`:
```
🏦 У тебя пока нет счетов.
Счёт — это место где хранятся деньги.

Создай первый:
[💳 Банковская карта]
[💵 Наличные]
[🔶 Крипто-биржа]
[₿  Крипто-кошелёк]
[✏️ Своё название]
```

Нажал [🔶 Крипто-биржа]:
```
Какая биржа?
[Binance] [Bybit] [OKX] [Kraken] [✏️ Другая]
→ Binance
В какой валюте?
[USDT] [BTC] [ETH] [✏️ Другая]
→ USDT
✅ Счёт «Binance» (USDT) создан!
```

### Phase 1.31 — Inline создание счёта при транзакции

**Зачем:** Пользователь упоминает место, которого нет в счетах — система предлагает создать на лету.

```
«Получил 1000 USDT с Binance»
→ Счёта «Binance» нет

💰 1,000 USDT с Binance.
Создать счёт «Binance»?

[✅ Создать «Binance» (USDT)]
[🏦 Выбрать другой счёт]
[📋 Записать без счёта]
```

Для неизвестной валюты:
```
«Получил 0.5 SOL»
→ SOL-счёта нет

💰 0.5 SOL. У тебя нет SOL-счёта.
[✅ Создать «SOL кошелёк» (SOL)]
[✏️ Другое название]
[🏦 На существующий счёт]
```

Fuzzy matching — нечёткий поиск:
```
«потратил на бинансе 100»
→ «бинансе» ≈ «Binance» (85% схожесть)
→ Берёт «Binance» молча, показывает в черновике
```

### Phase 1.32 — Умный текстовый ввод (добор информации)

**Зачем:** Одна и та же логика для текста и голоса — система никогда не застревает.

**Нет суммы:**
```
«Купил продукты»
→ 🛒 Продукты — понял. Сколько потратил?
> 2100
→ ✅ Расход: 2,100 USDT — Продукты [Подтвердить]
```

**Нет категории:**
```
«Потратил 3000»
→ 💸 3,000 USDT — на что потратил?
🏢 Бизнес: [Реклама] [Сервисы] [Налоги]
🌍 Жизнь:  [Продукты][Кофе]   [Транспорт]
[🔍 Найти] [✏️ Ввести вручную] [📋 Без категории]
```

Ввести вручную — inline creation:
```
✏️ Напиши название:
> Абонемент в зал
→ Такой нет. Создать?
[🏢 Бизнес] [🌍 Жизнь]
→ Жизнь
✅ Категория «Абонемент в зал» создана и применена.
```

**Неясен тип:**
```
«Дал Максу 5000»
→ 🤔 Это:
[🤝 Долг (он вернёт)]
[💸 Расход (не вернёт)]
```

**Бессмыслица:**
```
«ываыва» или «??????»
→ 🤔 Не понял.
[💸 Расход] [💰 Доход] [📊 Баланс] [📋 Отчёт] [✍️ Написать]
```

**Матрица уверенности AI (единая для текста и голоса):**
- 90–100%: показывает черновик, ждёт ✅
- 70–89%: показывает с пометкой «Верно?»
- 50–69%: показывает + кнопка «Нет, другое»
- < 50%: задаёт уточняющий вопрос
- 0%: меню «Что сделать?»

## БЛОК 4: Голос и Vision (Phase 2.1–2.3)

---

### Phase 2.1 — Голосовые транзакции (Whisper)

**Зачем:** Записывать траты голосом когда руки заняты.

```
🎤 «Потратил пятьсот USDT на рекламу»
→ Whisper: «Потратил 500 USDT на рекламу» (0.5 сек)
→ AI: расход, 500 USDT, Реклама (1 сек)
→ 💸 500.00 USDT — Реклама [✅ Верно] [✏️ Изменить]
```

Весь процесс: 3 секунды + одно нажатие.

При проблемах:
- Шум → «Не распознал. [🎤 Ещё раз] [✍️ Текстом]»
- Низкая уверенность → показывает варианты
- 3 неудачи подряд → «Попробуй текстом»

## Принципы продукта

1. **Никогда не угадывай молча** — если неуверен, спроси.
2. **Один вопрос за раз** — не перегружай пользователя.
3. **Всегда предлагай следующий шаг** — пользователь не застревает.
4. **Создавай сущности на лету** — категория, счёт создаются в процессе.
5. **Деструктивные действия = двойное подтверждение**.
6. **Храни как есть** — не конвертируй валюту без запроса.
7. **Баланс пересчитывается автоматически** при любом изменении.
