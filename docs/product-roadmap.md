- Clean Chat UX: edit-first strategy через Redis active-message pointer

- Inline account creation: создание счёта на лету при транзакции
- Smart Account Onboarding: guided onboarding при первом /start

- `/accounts`, `/add_account` — управление счетами
- `/category`, `/add_category` — управление категориями
- `/settings` — смена валюты (UI с пагинацией), timezone
- `/set_balance` — синхронизация баланса
- `/edit` — редактирование транзакций (сумма, категория, счёт, тип) + soft delete

### Phase 1.23 — `/set_balance` (Синхронизация баланса)

**Зачем:** Пользователь пересчитал деньги — в Midas показывает не ту сумму. Нужно быстро синхронизировать без записи фиктивных транзакций.

**Как работает:**

```
/set_balance Binance 48500

Система внутри:
  1. Находит счёт «Binance»
  2. Считает текущий баланс = initial_balance + Σтранзакций = 52 000
  3. Вычисляет новый initial_balance = 48500 − Σтранзакций
  4. UPDATE account_sources SET initial_balance = новое_значение
  5. Никакой транзакции не создаётся

Ответ бота:
✅ Баланс «Binance» синхронизирован
   Было:  52,000.00 USDT
   Стало: 48,500.00 USDT
```

**Ключевые правила:**
- Это НЕ расход и НЕ доход — техническая корректировка
- `/report` не затрагивается
- Категория не нужна
- Отрицательные значения разрешены (кредитка: `/set_balance Кредитка -65000`)
- Новых таблиц не нужно — используем существующий `initial_balance`

**Файлы:** `balance.service.ts` (MODIFY), `webhook.route.ts` (MODIFY), `smoke-test-phase123.mjs` (NEW)

### Phase 1.28 — `/edit` — редактирование транзакций

**Зачем:** Человек записал, подтвердил, а потом увидел ошибку. Нужно точечно исправить.

**Три способа найти транзакцию:**

Способ 1 — Последние (`/edit`):
```
/edit
📋 Последние транзакции:
1. 💸 Binance комиссия — 5.00 USDT      сегодня
2. 💰 Зарплата — 3,500.00 USDT          вчера
3. 💸 Продукты — 2,100.00 RUB           вчера
[◀️] 1/24 [▶️]
[🔍 Поиск] [❌ Закрыть]
```

Способ 2 — Поиск по тексту/сумме/дате:
```
🔍 Что ищем?
> кофе
→ 3 результата: [Кофе 350 RUB 03.05] [Кофе 420 RUB 28.04]...
```

Способ 3 — Постоянная кнопка в подтверждении:
```
✅ Записано: Кофе, 350 RUB, Расходы
[✏️ Изменить]  [📋 Детали]
```

Кнопка `[✏️ Изменить]` **не исчезает** — она остаётся навсегда в сообщении подтверждения. Пользователь может пролистать чат через неделю, нажать — и открыть карточку этой транзакции. Нет таймера, нет фонового worker'а, нет TTL. Telegram хранит callback_data в сообщении бессрочно.

**Карточка транзакции:**
```
📝 Транзакция
💸 Тип:      Расход
💰 Сумма:    350.00 RUB
📁 Категория: Кофе
🏦 Счёт:     Карта Сбер
📅 Дата:     03.05.2026

[✏️ Изменить сумму]
[📁 Изменить категорию]
[🏦 Изменить счёт]
[🔄 Изменить тип]
[🗑️ Удалить]
[◀️ Назад]
```

**Изменение категории:**
```
📁 Выбери новую:
🏢 Бизнес: [Реклама] [Сервисы] [Налоги]
🌍 Жизнь:  [Продукты][Кофе]   [Транспорт]
[🔍 Найти] [✏️ Ввести вручную]
→ ✅ Категория изменена. Баланс пересчитан.
```

**Изменение суммы:**
```
💰 Текущая: 350.00 RUB. Напиши новую:
> 380
→ ✅ Сумма изменена. Баланс пересчитан автоматически.
```

**Технические заметки:**
- Callback_data в Telegram ограничен 64 байтами — для сложных flow нужна таблица `callback_state` в БД для хранения состояния диалога
- Поиск по транзакциям: добавить GIN-индекс для full-text search по PostgreSQL, чтобы `LIKE '%кофе%'` не тормозил при 10k+ записей

### Phase 1.29 — Soft delete + удаление транзакций

**Принцип:** Двойное подтверждение. Данные не стираются физически.

```
[🗑️ Удалить]

⚠️ Удалить транзакцию?
💸 Кофе — 350.00 RUB — 03.05.2026
Баланс счёта изменится на +350.00 RUB.

[🗑️ Да, удалить]  [◀️ Отмена]
```

В базе: `UPDATE transactions SET deleted_at = NOW()` — soft delete.

**Требуется миграция:** `ALTER TABLE transactions ADD COLUMN deleted_at TIMESTAMPTZ DEFAULT NULL`.
Все существующие запросы (`balance.service`, `report.service`) должны добавить `WHERE deleted_at IS NULL`.

**Файлы:** миграция (NEW), `balance.service.ts` (MODIFY), `report.service.ts` (MODIFY), `webhook.route.ts` (MODIFY)

### Phase 1.31 — Inline создание счёта при транзакции

**Зачем:** Пользователь упоминает место, которого нет в счетах — система предлагает создать на лету. Не нужно уходить в `/add_account` — счёт создаётся прямо в процессе записи транзакции.

**Сценарий А — Новый пользователь, первая транзакция:**

```
«Получил 1000 USDT с Binance»
→ Счёта «Binance» нет

💰 Получил 1,000 USDT с Binance.
Создать счёт с таким названием?

[✅ Создать «Binance» (USDT)]
[🏦 Выбрать другой счёт]
[📋 Записать без счёта]
```

Нажал ✅ — счёт создан мгновенно, транзакция туда записана.

**Сценарий Б — Упоминает место которого нет в счетах:**

```
«Перевёл 500$ с PayPal на карту»
→ Счёта «PayPal» нет

🔄 Перевод 500 USD. Откуда: «PayPal» — такого счёта нет.

[✅ Создать счёт «PayPal» (USD)]
[🏦 Выбрать существующий]
[➡️ Записать как расход с Карты]
```

**Сценарий В — Неизвестная валюта:**

```
«Получил 0.5 SOL»
→ SOL-счёта нет

💰 0.5 SOL. Счёта нет. Создать?

[✅ Создать «SOL кошелёк» (SOL)]
[✏️ Другое название]
[🏦 На существующий счёт]
```

Нажал [✏️ Другое название]:
```
Как назовём SOL-счёт?

> Phantom Wallet

✅ Счёт «Phantom Wallet» (SOL) создан!
   Транзакция записана туда.
```

**Сценарий Г — Несколько подходящих счетов:**

```
«Потратил 200 USDT»
→ 2 USDT-счёта: Binance (2,847) и Bybit (500)

💸 200 USDT — с какого счёта?

[Binance  2,847 USDT]
[Bybit      500 USDT]
[✅ Создать новый]
```

**Сценарий Ж — Fuzzy matching (нечёткое совпадение):**

```
«потратил на бинансе 100»
→ «бинансе» ≈ «Binance» (85%) → берёт молча

💸 100 USDT с Binance
[✅ Верно]  [❌ Другой счёт]
```

Не создаёт дубль.

**Правило fuzzy match:** включается только для названий длиной ≥ 4 символа. Короткие тикеры (BTC, ETH, SOL) — только точное совпадение, чтобы избежать ложных срабатываний (BTC ≠ ETH).

**Полная архитектура — дерево решений:**

```
Транзакция пришла
         │
    Есть упоминание счёта/места?
         │
    ДА───┤                    НЕТ
         │                     │
  Ищем в базе            Один счёт
  по названию            в нужной
  (fuzzy match)          валюте?
         │                     │
    ┌────┴────┐            ДА──┘ Берём его
    │         │            НЕТ─┘ Спрашиваем
 НАШЛИ   НЕ НАШЛИ
    │         │
 Берём    Предлагаем
 счёт     создать
          с этим
          названием
          │
     Несколько
     счетов?
          │
     Предлагаем
     выбрать
```

### Phase 2.1 — Голосовые транзакции (Whisper)

**Зачем:** Записывать траты голосом когда руки заняты. Весь процесс: 3 секунды + одно нажатие.

Норма (happy path):
```
🎤 «Потратил пятьсот USDT на рекламу»
→ Whisper: «Потратил 500 USDT на рекламу» (0.5 сек)
→ AI: расход, 500 USDT, Реклама (1 сек)
→ 💸 500.00 USDT — Реклама [✅ Верно] [✏️ Изменить]
```

**Классификация проблем:** Технические (шум, молчание, не тот язык) и смысловые (неясен интент, неполные данные, противоречия).

---

**Блок 1: Технические проблемы — не распознан голос**

Случай 1.1 — Шум, неразборчиво (Whisper вернул пустую строку или мусор):
```
😕 Не смог разобрать голосовое.

Возможные причины:
• Слишком тихо или шумно вокруг
• Слишком короткое сообщение
• Соединение прервалось

[🎤 Записать ещё раз]
[✍️ Написать текстом]
[❌ Отмена]
```

Случай 1.2 — Молчание (продолжительность < 1 секунды):
```
🔇 Голосовое пустое — ничего не записал?

[🎤 Попробовать снова]  [❌ Отмена]
```

Случай 1.3 — Не тот язык (Whisper распознал, но абракадабра):
```
🌐 Распознал, но не уверен в языке.

Ты имел в виду:
«[транскрипция]»?

[✅ Да, это верно]
[🎤 Повторить по-русски]
[✍️ Написать текстом]
```

---

**Блок 2: Смысловые проблемы — после транскрипции**

Добор недостающей информации (нет суммы, нет счёта, нет категории, неясен тип, бессмыслица) — **идентичен Phase 1.32**. Транскрипция Whisper обрабатывается тем же Intent Router'ом.

Смешанный intent (два запроса в одном):

2️⃣ Показать баланс

[✅ Сначала запись]  [📊 Только баланс]
```

Противоречивые данные:

🤔 Ты имеешь в виду:

```

**Матрица уверенности AI — как система принимает решения:**

```
Уверенность     Действие системы
──────────────────────────────────────────────
90–100%    →  Выполняет, показывает подтверждение
             «Записал расход 500 USDT — верно?»

70–89%     →  Выполняет, но подчёркивает неуверенность
             «Кажется, это расход 500? Проверь 👇»

50–69%     →  Показывает вариант + кнопку «Нет, не то»
             [✅ Да]  [❌ Нет, другое]

< 50%      →  Не угадывает. Показывает меню вариантов.
             «Не понял. Что ты хочешь сделать?»

0%         →  Полная неразборчивость → просит повторить
```

[✍️ Написать текстом]
[❌ Отмена]

Система сама предлагает выход. Не зависает. Не раздражает.

### Phase 1.35 — Intelligent Transaction Understanding ✅

**Зачем:** AI извлекал только intent/amount/currency. Не понимал «что именно купили», «в какой категории», «с какого счёта». Каждая транзакция была безликой.

**Что реализовано:**

**AI-слой:**
- `item_hint` — название товара/услуги/места (`«кофе в Старбаксе»` → `item_hint: "кофе"`)
- `category_hint` — подсказка для автокатегоризации (`«продукты»`, `«реклама»`)
- Промпт Claude Haiku обновлён: 40+ категорий расхода, 15+ дохода, 25+ примеров

**Категоризация:**
- `CategoryResolverService` (NEW): 3-этапный пайплайн
  1. **Exact match**: `WHERE LOWER(name) = LOWER($1)` — прямое совпадение по названию
  2. **Alias match**: 200+ маппингов (`кофе`→`Кофе`, `uber`→`Транспорт`, `реклама`→`Маркетинг`)
  3. **Fallback**: категория «Другое» (ulid, автосоздание)
- 28-категорийная таксономия с двумя группами: `Жизнь` (18 категорий) и `Бизнес` (10 категорий)

**Rich preview (все 8 точек входа):**
- `confirmPreview()` + `confirmKb()` — централизованные helper'ы в webhook.route.ts
- Все точки входа в confirmation (clarification суммы, выбор типа, выбор категории, выбор счёта, inline account creation) показывают полную карточку транзакции

## БЛОК 6: Автоматизация (Phase 2.6–2.7)

---

### Phase 2.6 — Регулярные транзакции (`/recurring`)

**Зачем:** Пользователь каждый месяц платит за VPN, подписку, аренду. Вводить одно и то же каждый раз — лишнее. Система умеет напоминать и ждёт подтверждения.

**Два способа создания — работают одновременно:**

**Способ А — Умное предложение системы (автоматически):**

Система замечает паттерн — 3+ похожих транзакции с регулярным интервалом:

```
✅ Записано: VPN — 50.00 USDT

💡 Вижу, ты записываешь это каждый месяц.
   Сделать автоматическим напоминанием?

[🔄 Да, каждый месяц]  [❌ Нет, это разово]
```

Предложение появляется только на 3-й раз. Не раньше. Не раздражает.

**Способ Б — Ручное создание через `/recurring`:**

```
/recurring

🔄 Регулярные платежи:
1. VPN — 50.00 USDT — каждый месяц (след: 1 июня)
2. Аренда — 800.00 USDT — каждый месяц (след: 5 июня)

[➕ Добавить]  [✏️ Изменить]  [❌ Закрыть]
```

Нажал [➕ Добавить]:

```
Что за платёж?
> Spotify 9.99 USDT

Как часто?
[Каждый месяц]  [Каждую неделю]  [Каждый год]

Какого числа?
[1-го]  [5-го]  [15-го]  [Последний день]  [✏️ Другое]

✅ Spotify — 9.99 USDT — каждый месяц, 1-го числа
```

**Как работает напоминание (в день платежа, 09:00):**

```
🔔 Регулярный платёж:
💸 Spotify — 9.99 USDT

[✅ Записать]  [⏭️ Пропустить]  [✏️ Изменить сумму]
```

Бот НЕ записывает автоматически — только напоминает и ждёт нажатия.
Причина: сумма могла измениться, подписка могла быть отменена.

**Настройка уведомлений:**

```
/recurring settings

🔔 Напоминания о регулярных платежах:
[✅ Включены]  ← нажми чтобы выключить

Когда напоминать:
[В день платежа]  [За день]  [За 3 дня]
```

### Phase 2.7 — Бюджеты / Лимиты (`/budget`)

**Зачем:** Контроль трат по категориям. Система информирует при приближении к лимиту — но никогда не блокирует запись транзакции.

**Как устанавливается:**

```
/budget → [➕ Создать бюджет]
→ Выбор категории: [Кофе]
→ Сколько USDT максимум? > 200
→ Период: [Месяц]

✅ Кофе — до 200 USDT / месяц
```

**Как отображается `/budget`:**

```
📊 Бюджеты за Май 2026:

☕ Кофе:        87 / 200 USDT (44%)
   [████░░░░░░] Осталось: 113

📢 Реклама:   1,800 / 2,000 USDT (90%)
   [█████████░] ⚠️ Осталось: 200

🛒 Продукты:  2,400 / 2,000 USDT (120%)
   [██████████] 🔴 Превышен на 400
```

**Когда приходят уведомления (привязаны к моменту записи транзакции):**

Порог 80% — мягкое предупреждение (строчка в ответе на транзакцию):

```
✅ Записано: Кофе — 35.00 USDT

⚠️ Бюджет на Кофе: 165 / 200 USDT (82%)
   Осталось 35 USDT до конца месяца.
```

Порог 100% — превышение:

```
✅ Записано: Кофе — 40.00 USDT

🔴 Бюджет на Кофе превышен!
   210 / 200 USDT (+10 сверх лимита)

[📊 Подробнее]  [😌 Ок, понял]
```

1-го числа каждого месяца — итог за прошлый месяц:

```
📊 Итоги бюджетов за Апрель 2026:

✅ Кофе:      180 / 200 USDT — в норме
⚠️ Реклама: 1,950 / 2,000 USDT — почти предел
🔴 Продукты: 2,400 / 2,000 USDT — превышен на 400
```

**Настройка уведомлений:**

```
/budget settings

🔔 Уведомления:
[✅ При 80%]       ← мягкое предупреждение
[✅ При 100%]      ← превышение
[✅ Итог месяца]   ← 1-го числа

[🔕 Отключить все]
```

Пользователь может отключить любой порог отдельно или все сразу.
**Бюджет никогда не блокирует запись транзакции** — только информирует.

## Принципы продукта

1. **Никогда не угадывай молча** — если неуверен, спроси.
2. **Один вопрос за раз** — не перегружай пользователя.
3. **Всегда предлагай следующий шаг** — пользователь не застревает.
4. **Создавай сущности на лету** — категория, счёт создаются в процессе.
5. **Деструктивные действия = двойное подтверждение**.
6. **Храни как есть** — не конвертируй валюту без запроса.
7. **Баланс пересчитывается автоматически** при любом изменении.
8. **Бюджет информирует, но не блокирует** — пользователь всегда может записать.
9. **Напоминай, не автоматизируй** — регулярные платежи ждут подтверждения.
10. **Бот — для ввода, Mini App — для анализа** — каждый инструмент в своей роли.
11. **Не добавляй внешних зависимостей без необходимости** — каждый API (Whisper, CoinGecko, Notion) = точка отказа.
12. **Rate limiting** — защита от спама команд и Telegram API лимитов (~30 msg/sec).
